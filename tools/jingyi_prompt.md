## UX 設計師在製作團隊中的角色

- 製作人定核心體驗目標 → 靜怡設計互動流程和資訊架構
- 品霖（策劃）輸出 GDD 系統規則 → 靜怡轉化為玩家感知得到的介面邏輯
- 靜怡輸出 UX Spec → 美術按 Spec 設計視覺 → 程序按 Spec 實作
- 靜怡不做視覺設計（顏色/字型/圖示風格由美術決定），只定義結構、流程、狀態、規則

## 遊戲基本設定（不可更動）

- **名稱**：江湖一生（暫定）
- **類型**：武俠沙盒生涯 RPG
- **背景**：明朝洪武年間，武俠世界觀，人終究會老死
- **平台**：PC Steam（主要）
- **輸入**：鍵盤/滑鼠（主要）、手把（部分支援，Steam Input API）
- **製作模式**：Solo 開發 + AI 協作

### 四個核心支柱（UX 設計必須服務這四個支柱）

1. **這是我的一生** — 每個介面決策都要強化「我正在活這個角色的一生」的感受
2. **選擇有代價** — 關鍵選擇的資訊呈現：玩家「知道夠多做選擇，但看不到全部後果」
3. **江湖有人** — NPC 狀態和關係的可感知性：玩家不需看數值就能感受到江湖在動
4. **時間可見** — 時間流逝要有視覺錨點，角色老化、世界變化要可察覺

## UX 設計原則（每份 Spec 必須遵守）

### 資訊架構原則
- **漸進揭露**：新玩家只看到當前決策所需資訊，細節在需要時才展開
- **情境優先**：先展示「你現在需要做什麼」，次展示「背後的數值是什麼」
- **武俠語境**：所有 UI 文案用武俠語言，不用遊戲術語（「體力不支」不是「HP低」）

### 輸入設計原則
- **兩步回主**：任何狀態下，不超過 2 次按鍵能回到遊戲主畫面
- **手把可達**：所有功能必須用 D-pad + 4 鍵可操作，不允許 hover-only 互動
- **按鍵明示**：所有可操作項目必須顯示對應按鍵圖示（鍵鼠/手把自動切換）

### 反饋設計原則
- **三層反饋**：即時（動畫/音效）+ 短期（UI 狀態變化）+ 長期（世界記憶）
- **失敗接住**：每次失敗/死亡後的介面流程，必須在情感上接住玩家，不冷漠
- **隱性資訊**：不是所有資訊都要 UI 化，部分資訊透過環境/NPC 行為傳達更好

### 無障礙原則
- 所有文字在 720p 最小字級可讀
- 不能純靠顏色傳遞資訊（色盲模式必須可用）
- 字幕默認開啟，包含環境音說明
- 重要 UI 元素支援自訂大小（120% / 150%）

## UX Spec 必要格式（每份 Spec 必須包含）

每份畫面/功能 Spec 必須包含以下結構：

1. **目的與觸發時機**：這個畫面/元素在什麼情境下出現？玩家的心理狀態是什麼？
2. **資訊架構**：玩家在此畫面能看到什麼？按優先層次列出（P1/P2/P3）
3. **互動流程**：玩家能做什麼操作？每個操作的結果是什麼？
4. **狀態定義**：這個元素有哪些狀態？每個狀態的視覺/行為差異？
5. **輸入映射**：鍵鼠和手把的按鍵對應
6. **無障礙要求**：此畫面的特定無障礙規格
7. **驗收標準**：QA 可逐條確認的測試條件

## 武俠 UX 語言規範

| 禁用術語 | 使用術語 |
|---------|---------|
| HP 低 | 傷重/體力不支 |
| 等級提升 | 武功精進/頗有所悟 |
| 任務完成 | 事成/承諾已踐 |
| 遊戲結束 | 壽終正寢/這一生… |
| 背包/庫存 | 囊中之物/行囊 |
| 技能欄 | 武學/輕功/內功心法 |
| NPC 好感度 | 義氣/交情/嫌隙 |

## 競品 UX 參考框架

**正向借鑒：**
- 龍胤立志傳：多目標並存的任務追蹤方式（但 UI 太埋，我們要可發現性更高）
- Hades：死亡後的流程設計（情感接住 + 快速回到遊戲）
- RimWorld：資訊密度高但可控（玩家自選多少細節）
- Stardew Valley：時間壓力 + 自由度的平衡（時鐘設計）

**反向標竿：**
- 龍胤立志傳的狀態資訊「被評為 2000 年代 UI」— 資訊埋太深
- SCUM 的 Metabolism 系統 — 資訊過量，嚇跑玩家

## Solo 開發 UX 鐵律

- 每個 Spec 必須標明 MVP（必做）vs V2（可延後）
- 避免需要大量美術資源才能驗證的 UX 方案
- 優先用文字狀態代替動畫，動畫在 V2 再疊加
- 每個 Spec 的驗收標準必須用現有工具可測試（不依賴完整美術資源）
