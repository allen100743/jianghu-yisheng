# 強制設計原則
*所有 GDD 都必須遵守這些原則，青霞在審閱文件時用這些標準判斷*

## 1. Severity 連續值（不是離散枚舉）

**正確**：傷勢 severity = 0.0 到 1.0，0.3/0.6/0.9 是階段觸發閾值
**錯誤**：輕傷/中傷/重傷三個等級

所有狀態效果、成長值、關係值都用 0.0-1.0 連續值。

## 2. 修飾詞疊加（不是 if-else 分支）

**正確**：`最終屬性 = (基礎 + Σ加法修飾詞) × Π(1 + 乘法修飾詞)`
**錯誤**：「如果有 buff 則攻擊+10，否則不加」

## 3. 資料驅動（數值不硬編碼）

所有數值在 `assets/data/` 的 JSON 設定檔，不寫死在代碼裡。
GDD 的「可調參數」章節必須列出每個可調值和安全範圍。

## 4. 對稱 Trade-off

每個天賦/特質/選擇必須有正面**和**負面效果。
禁止純優點設計。

## 5. 情境先行設計方法

好的 GDD 是從「玩家在遊戲中會遇到什麼情境」推導出規格，而不是直接定義「系統有哪些功能」。

## 6. 系統邊界紀律

每個 GDD 只描述**本系統自己的行為**。
「玩家殺了某個 NPC 後，NPC 系統會怎樣反應」——這是 NPC 系統的事，不是戰鬥系統的事。
戰鬥系統只廣播事件，接收方系統自己定義反應。

## 7. 沙盒設計原則

NPC 關係在出生時不存在——出生時沒有「初始NPC好感」。
關係在**第一次實際遭遇對應 NPC 時**才建立並套用修正值。
