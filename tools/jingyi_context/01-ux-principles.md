# UX 設計原則 — 本作強制規範

## 核心哲學：UI 是最後手段

能靠環境傳達的資訊，不出現在 UI。
能靠 NPC 行為傳達的狀態，不用數值顯示。
UI 只承載「玩家必須知道，但無法從世界中感知」的資訊。

---

## 資訊架構原則

### 漸進揭露三層（所有畫面強制）
- **P1（即時可感知）**：常駐顯示，不需玩家主動查詢
- **P2（按需展開）**：懸停/選中後顯示
- **P3（主動查詢）**：開啟面板才可見

### 「夠多但不全部」原則（關鍵決策時）
玩家在做重要決定（拜師、結義、任務、仇恨）前：
- 給：選擇的即時效應（我現在能感知到的代價）
- 不給：長期後果的完整清單（玩家應自行推導）
- 不給：精確數值公式

---

## 武俠語境規範（嚴格執行）

| 禁用術語 | 使用術語 |
|---------|---------|
| HP 低 / 血量不足 | 傷重 / 體力不支 / 命在旦夕 |
| 等級提升 | 武功精進 / 頗有所悟 |
| 任務完成 | 事成 / 承諾已踐 / 義不容辭 |
| 遊戲結束 | 壽終正寢 / 這一生… |
| 背包 / 庫存 | 囊中之物 / 行囊 |
| 技能欄 | 武學 / 內功心法 |
| NPC 好感度 | 義氣 / 交情 / 積怨 |
| 任務失敗 | 失諾 / 負人心 |
| 任務無效（INVALIDATED）| 無緣 / 世事弄人 |
| 任務放棄 | 辜負 / 轉身而去 |

### 情境句格式（浮框/通知必須遵守）
不直接說「你的外傷 severity = 0.45」，改用：
「傷口見骨，血染衣襟，疼痛難當」（描述狀態的感受，不是數值）

---

## 輸入設計原則

- **兩步回主**：任何介面，不超過 2 次按鍵/點擊可回到遊戲主畫面
- **手把可達**：所有功能必須用 D-pad + 4 鍵可完整操作
- **按鍵明示**：可互動元素必須顯示對應按鍵圖示，鍵鼠/手把自動切換
- **不允許 hover-only**：任何只靠滑鼠懸停才能觸發的功能，手把必須有等效操作

---

## 反饋設計原則

### 三層反饋（每個系統事件都需要）
1. **即時**：動畫 / 音效（0.1-0.5 秒）
2. **短期**：UI 狀態變化（數秒）
3. **長期**：世界記憶 / NPC 行為改變（持續存在）

### 失敗接住設計
死亡/失敗後的介面流程要「在情感上接住玩家」：
- 不冷漠跳出「遊戲結束」畫面
- 死亡結算要讓玩家感受到「這一生有意義」
- 快速回到遊戲的路徑要清晰，但不強迫

---

## 無障礙底線（每份 Spec 必須符合）

- 最小字級：720p 下可讀
- 不純靠顏色傳遞資訊（色盲模式）
- 所有 UI 元素手把可達
- 字幕默認開啟（含環境音說明）

---

## Solo 開發 UX 鐵律

每份 Spec 必須標明：
- **MVP**：最小可驗證版本（可用文字狀態代替動畫）
- **V2**：動畫、精細視覺表現、進階功能
- **明確不做**：防止範圍膨脹

優先可用文字狀態替代動畫——動畫在 V2 疊加。
