# 競品 UX 研究筆記

*來源：靜怡業界研究 + 社群評論分析 | 2026-05-12*

---

## 狀態效果 UI 業界方案

### 研究結論（已應用到 status-effects-hud spec）

**推薦方向**：嚴重度優先排序型 + 三層視覺語言 + 武俠語境文案

**三層視覺語言規格**：
- 圖示填充度（0-100% 反映 severity）
- 3px micro-bar（顏色隨段位）
- 脈衝動畫（severity ≥ 0.9 時）

**自動排序**：`severity × 惡化速率係數 × 致死風險係數`，≥ 0.9 強制置頂

**危急觸發**：首次進入閾值時一次性動畫，之後靜態光暈（避免持續閃爍讓玩家脫敏）

## 競品分析

### 龍胤立志傳

**L2 玩家體驗（社群評論）**：
- 「UI 太像 2000 年代」「資訊埋太深，找不到」
- 好評：多重目標並存的任務追蹤邏輯
- 差評：狀態資訊藏在不直覺的地方，玩家需要多次點擊才找到

**對我們的啟示**：
- ✅ 借鑒：多目標任務追蹤的邏輯架構
- ❌ 避免：重要狀態資訊可發現性低
- 修正方向：同樣的資訊密度，但入口要在玩家注意力自然落點

### 鬼谷八荒

**L1 功能層**：
- 狀態 icon 排列型，但無 severity 視覺化
- 「有/無」二元標籤，不適合我們的連續值設計
- 技能詳情頁資訊密度高但層次清晰

**L2 玩家體驗**：
- 正面：戰鬥回饋爽快，即時感強
- 負面：修仙感太強，不適合武俠

**對我們的啟示**：
- ✅ 借鑒：技能詳情頁的資訊層次（主要效果 → 詳細說明 → 數值）
- ❌ 不借鑒：「有/無」狀態標籤（我們需要 severity 連續值視覺化）

### RimWorld

**L1 功能層**：
- 文字優先型 + 顏色 = 嚴重度
- Health Tab 細節豐富，社群 mod「Nice Health Tab」人體剪影廣受好評

**L2 玩家體驗**：
- 「資訊多但玩家可以選擇看多少」
- 詳細面板適合深度玩家，表層 HUD 適合快速判斷

**對我們的啟示**：
- ✅ 借鑒：詳細面板的文字優先設計（P3 層）
- ✅ 借鑒：玩家可以選擇深度的設計哲學（漸進揭露）

### Hades

**L2 玩家體驗**：
- 死亡後流程設計是業界標竿
- 情感接住 + 快速回到遊戲 + 故事繼續推進

**對我們的啟示**：
- ✅ 借鑒：死亡結算的情感設計——讓玩家感覺「死了但不是白死」
- 應用到「壽終正寢」結算畫面設計

### Stardew Valley

**L2 玩家體驗**：
- 時間壓力 + 自由度的平衡
- 時鐘的設計讓時間流逝感非常自然

**對我們的啟示**：
- ✅ 借鑒：時間流逝的視覺錨點設計（季節/天氣/時鐘）

### SCUM（反向標竿）

**L2 玩家體驗**：
- Metabolism 系統「嚇跑人」，資訊過量
- 玩家評論：「我只是想玩，不是來上生物課的」

**對我們的啟示**：
- ❌ 避免：把所有後台數值都暴露給玩家
- 設計禁忌：讓玩家感覺在管理電子表格，而不是活在江湖裡

## 武俠 UI 特殊考量

### 時間系統 UX 參考
- 龍胤立志傳的「日曆+年齡」顯示讓玩家有明確時間感
- 我們要做得更武俠：不顯示「距死亡還有X天」，而是「年邁體衰，風中殘燭」

### 多 NPC 關係 UX 參考
- 大多數武俠遊戲用數值條顯示好感度
- 我們的設計禁忌：不顯示精確關係數值
- 替代方案：用 NPC 對話語氣、行為、稱呼變化傳達關係程度

### 任務 UX 的武俠化
- 傳統任務 UI：清單 + 進度條 + 獎勵預覽
- 我們的方向：「承諾日誌」而非「任務清單」，強調承諾和選擇的道德重量
