這次的分析，我將從一個資深策劃的角度，直接切入核心：HOI4 的設計哲學對我們《江湖一生》的開發有著極高的參考價值，尤其是其「資料驅動」和「修飾詞疊加」的架構，幾乎是為我們這種需要高度動態、且由 Solo 開發者（搭配 AI）執行的沙盒遊戲量身打造。

### 1. 競品系統架構對照

| HOI4 系統 | 《江湖一生》現狀 | 分析與行動建議 |
| :--- | :--- | :--- |
| **事件系統** | ✅ **我們已有概念** | GDD 第 4、7、8、9 章皆有提及事件觸發。但我們的設計偏向「觸發結果」，缺乏 HOI4 那種「事件鏈」和「條件化敘述」的結構化思維。**需要強化。** |
| **決策系統** | ⚠️ **設計明顯不同** | 我們的「選擇」散落在各系統中，是玩家行動的副產物。HOI4 的決策系統是一個獨立、有時限、有明確成本的「機會視窗」。這更符合「選擇有代價」的核心支柱。**值得補充。** |
| **修飾詞系統** | ❌ **我們沒有** | 這是最大的架構差距。我們的屬性計算是線性的（基礎 + 裝備 + 武學）。HOI4 的修飾詞疊加是動態、可疊加、可自動啟停的。這對實現「中毒、受傷、憤怒、buff」等即時狀態至關重要。**必須引入。** |
| **資料驅動哲學** | ❌ **我們沒有** | GDD 沒有定義數據配置的架構。這對 Solo 開發是致命缺陷。所有數值硬編碼在 GDScript 中，會讓平衡調整變成一場噩夢。**必須引入。** |
| **AI 權重系統** | ⚠️ **設計明顯不同** | 我們 GDD 第 7 章提到 NPC 有「記憶」，但未定義其行為決策邏輯。HOI4 的 `ai_will_do` 權重提供了一個可配置、可預測的框架，讓 NPC 行為不再是純隨機。**值得補充。** |

### 2. 數值設計啟示

HOI4 的數值設計非常務實，對我們有具體參考價值：

- **百分比優先於固定值**：HOI4 大量使用 `+10%`、`-20%` 這類百分比修飾。這比「武力 +5」更靈活，能與基礎屬性產生化學反應，且後期不至於通貨膨脹。
    - **建議：** 我們的裝備詞條、武學效果、狀態效果，應優先設計為百分比。例如，一把「寶刀」的效果不該是「武力+10」，而是「外功傷害 +15%」。
- **組合成本**：HOI4 決策的成本可以是 `金錢 AND 影響力`。這啟發我們，一個高價值的「選擇」（如暗殺掌門）不應只消耗銀兩，還應消耗「江湖人脈」或「門派貢獻」。
- **門檻設計**：HOI4 的觸發條件非常明確（`has_war`、`has_army_size > 50`）。這對我們定義事件觸發條件很有幫助，應避免模糊的「名聲夠高」，而是設定為 `名聲值 >= 500`。
- **避免的數值設計**：HOI4 的數值有時為了模擬歷史而過於複雜（如各種生產效率的修正）。我們是武俠沙盒，數值設計應服務於「戲劇性」和「成長感」，而非擬真。例如，不需要設計「武器磨損度」這種純數值消耗。

### 3. 技能/內容設計規律

HOI4 的「技能」是國家焦點樹（National Focus Tree），其命名模式是**「動詞 + 名詞」**，清晰有力：
- `「重整軍隊」`、`「發展工業」`、`「宣稱領土」`

這對我們武學系統的命名有直接啟發：
- **現有 GDD 問題**：我們的武學名稱（太祖長拳、華山劍法）是好的，但「效果描述」太像數值說明了。
- **建議調整**：將武學效果描述從「武力+20%」改為有畫面的短語。
    - **外功（狂風刀法）**：`「每三刀疊加一層『狂風』，疊滿五層後下一擊必為暴擊。」` -> **命名規律**：`[流派][動作][效果]`
    - **內功（龜息功）**：`「運功時存在感大幅降低，移動速度減半，但內力恢復速度提升三倍。」` -> **命名規律**：`[狀態][代價][收益]`
    - **輕功（梯雲縱）**：`「短時間內獲得一次無視地形的跳躍能力，落地後進入短暫的力竭狀態。」` -> **命名規律**：`[功能][限制]`

**分層規律**：HOI4 的焦點樹有明確的前置關係。我們也應在武學設計中引入：
- **入門 → 熟練 → 精通**：這在 GDD 已有，很好。
- **前置武學**：例如，想學「奪命十三劍」的第四劍，必須先將前三劍練至「大成」。這能創造更深的養成路徑。

### 4. 我們 GDD 的設計空白

從 HOI4 的架構來看，我們 GDD 有以下重要空白：

1.  **獨立的事件鏈系統**：GDD 的事件是零散的。我們需要一個**全局事件管理器**，能定義事件的觸發條件、選項、選項後果，以及最重要的——**事件鏈**。一個事件可以觸發另一個事件，形成連鎖反應。
    - **武俠適配**：非常適合。例如：「你救了村長的女兒（事件A）」→「村長感激你，告訴你一個寶藏線索（事件B）」→「你前往尋寶，卻發現寶藏已被仇家捷足先登（事件C）」。
2.  **時限性決策系統**：我們缺少一個「機不可失」的機制。玩家不應該能無限期地考慮一個重要決定。
    - **武俠適配**：非常適合。例如：「你在客棧聽到有人密謀刺殺知府。你只有三天時間決定是去告密、還是加入他們、還是假裝沒聽見。」 (`days_remove = 3`)
3.  **全局修飾詞管理器**：這不是一個系統，而是**整個遊戲的數值架構**。我們必須設計一個 `ModifierManager`，讓所有狀態（buff/debuff/裝備/武學）都以修飾詞的形式動態疊加到角色屬性上。
    - **武俠適配**：這是底層架構，與世界觀無關。它是實現「中毒後武力下降，但內力恢復速度提升」這類複雜狀態的唯一可行方案。
4.  **NPC 行為權重表**：我們需要定義每個 NPC 的「性格」，並將其映射到一組決策權重上。
    - **武俠適配**：非常適合。一個「俠義之士」性格的 NPC，在面對「賄賂」選項時，`ai_will_do` 權重為 0；而一個「貪財」的 NPC，權重則為 90。

### 5. 競品設計缺陷（我們要避免的）

1.  **複雜的 UI 與學習曲線**：HOI4 的 UI 對新玩家極不友好，資訊密度過高。我們必須避免。**解決方案**：UI 設計遵循「漸進式揭露」，玩家初期只看到核心資訊，進階功能隨遊戲進程逐步解鎖。
2.  **「微操」地獄**：HOI4 後期，玩家需要管理數百個師團，操作繁瑣。**解決方案**：我們的戰鬥支援自動戰鬥，NPC 關係有「代管」選項（如委託義兄弟處理某地事務），避免玩家在後期陷入繁瑣的日常管理。
3.  **AI 行為可預測性過高**：HOI4 的 AI 有時會做出「為了模擬歷史而放棄最優解」的愚蠢行為。**解決方案**：我們的 NPC 行為應基於其「性格、記憶、利益」的加權隨機，而不是固定腳本。讓 NPC 的「不完美」和「非理性」成為戲劇性的來源。

### 6. 對現有 GDD 的具體修訂建議

基於以上分析，我建議對 GDD 進行以下修訂：

#### 需要補充的 GDD 章節

1.  **新增章節：15. 全局事件與決策系統**
    - **15.1 事件結構定義**：定義事件（`Event`）的數據結構，包含 `id`、`觸發條件`（Trigger）、`條件化敘述`（多種文本）、`選項`（Option，含 `ai_will_do` 權重）、`後果`（Effect，可觸發另一事件）。
    - **15.2 決策系統**：定義決策（`Decision`）的數據結構，包含 `可見條件`、`可用條件`、`成本`（多資源組合）、`時限`（`days_remove`）、`完成效果`。
    - **15.3 事件鏈設計原則**：說明如何用多個小事件構成複雜的江湖故事，並提供範例（如「客棧密謀」事件鏈）。

2.  **新增章節：16. 數值架構：修飾詞系統**
    - **16.1 核心概念**：解釋「疊加取代分支」的設計哲學。
    - **16.2 修飾詞定義**：定義修飾詞（`Modifier`）的數據結構，包含 `目標屬性`、`修改類型`（百分比/固定值）、`值`、`啟用條件`（可選）。
    - **16.3 最終屬性計算公式**：`最終屬性 = 基礎屬性 × 所有百分比修飾詞的乘積 + 所有固定值修飾詞的總和`。
    - **16.4 動態修飾詞範例**：列出中毒、受傷、狂怒、輕功加成等狀態的修飾詞配置範例。

3.  **新增章節：17. NPC 行為架構**
    - **17.1 NPC 性格定義**：定義 NPC 的性格維度（如：善惡、勇氣、貪婪、忠誠），每個維度 1-100 分。
    - **17.2 行為權重表**：定義一個全局表格，將「性格維度」映射到「對事件選項的 `ai_will_do` 權重修正」。
    - **17.3 NPC 決策流程**：`收到事件 → 讀取性格 → 計算各選項權重 → 加權隨機選擇 → 執行`。

#### 需要調整的數值設計

- **屬性成長**：將 GDD 14.1 中的「成長上限」改為「理論上限」，實際成長應受修飾詞影響，可以短暫突破。
- **裝備詞條**：將 GDD 14.5 中的「基礎數值範圍」改為「提供一個基礎數值 + 一個或多個百分比修飾詞」，例如：「寶器級別的劍：武力 +50，外功傷害 +10%」。
- **世界感知**：將傳播速度公式從 `30里/天 × (1 + 名聲/100)` 改為「基礎速度 30里/天，加上一個來自名聲的百分比修飾詞」。

#### 建議新增的系統/機制

- **「機會視窗」提示UI**：當一個時限性決策出現時，在螢幕邊緣出現一個圖示，提示玩家「還有 X 天可以決定」，增加緊迫感。
- **「事件日誌」系統**：記錄玩家經歷過的重大事件，不僅是任務記錄，而是像一本「江湖回憶錄」，讓玩家回顧自己的一生是如何被選擇塑造的。

---

**總結：**

製作人，HOI4 的數據對我們最大的價值，不在於它的內容，而在於它的**工程架構**。我們必須將「資料驅動」和「修飾詞系統」作為《江湖一生》的底層設計原則。

這能讓一個 Solo 開發者（搭配 AI）在**不重構核心代碼**的情況下，透過修改 JSON 配置檔，就能創造出近乎無限的遊戲內容和動態變化。這才是我們能「活」下來的關鍵。
