## 3. 提出下一步：最應該先輸出的文件

我認為現在最應該先輸出的文件是：

### **《核心沙盒模擬概念文件》**

#### 理由

製作人已經說得很清楚：MVP的核心驗證目標是「沙盒世界能不能跑起來——NPC像真人一樣生活、有人際關係、會做自己該做的事」。

這份文件的目的是**把「沙盒世界活起來」這個模糊目標，轉化為具體可執行的系統設計**。它會回答以下問題：

1. **NPC的「一天」是怎麼過的？** 他們的行為邏輯是什麼？
2. **NPC之間的關係是怎麼建立、維持、破裂的？**
3. **世界感知系統（消息傳播）的具體運作邏輯是什麼？**
4. **玩家的行為如何影響NPC和世界？**
5. **MVP階段，這個沙盒的最小可驗證版本長什麼樣？**

這份文件會是後續所有系統設計的基礎——角色創建、戰鬥、裝備、經濟，最終都要服務於這個「活的沙盒」。

---

#### 文件大綱

```
# 核心沙盒模擬概念文件

## 1. 設計目標
   - 一句話定義：「沙盒世界活起來」是什麼意思
   - MVP驗證標準：玩家進入世界後，能在多長時間內感受到「這個世界是活的」
   - 非目標：哪些東西是MVP階段不做的（避免範圍蔓延）

## 2. NPC 行為模型（核心引擎）
   - 2.1 NPC 的每日循環：起床→活動→休息，具體活動類型（工作、練武、社交、閒逛等）
   - 2.2 NPC 的目標驅動：每個NPC有自己的短期目標（今天要做什麼）和長期目標（這輩子想達成什麼）
   - 2.3 NPC 的決策邏輯：如何根據自身屬性、關係、環境做出選擇（簡單的權重系統）
   - 2.4 NPC 的記憶系統：記得什麼（玩家的行為、重要事件）、忘記什麼（細節、過期資訊）

## 3. 人際關係動態系統
   - 3.1 關係類型與初始狀態：陌生人→熟人→朋友/仇人/戀人/師徒等
   - 3.2 關係變化觸發條件：玩家行為、NPC之間互動、時間流逝
   - 3.3 關係的「繼承」邏輯：仇家後代、舊日盟友的後代等（為傳代系統鋪路，但MVP可簡化）

## 4. 世界感知系統（消息傳播）
   - 4.1 事件生成：玩家或NPC的行為如何變成「消息」
   - 4.2 傳播邏輯：距離衰減、時間延遲、NPC社交網絡
   - 4.3 消息失真：以訛傳訛的機制（簡單版：消息強度隨傳播次數衰減）
   - 4.4 NPC對消息的反應：消息如何影響NPC的決策和行為

## 5. 玩家行為與世界回應的鏈路
   - 5.1 玩家行為 → 事件生成 → 消息傳播 → NPC反應 → 世界變化
   - 5.2 舉例：玩家在A城殺了人 → A城NPC恐懼/報官 → 消息傳到B城 → B城的仇人知道玩家來了 → 仇人設下陷阱
   - 5.3 MVP階段需要驗證的「最小閉環」

## 6. MVP沙盒範圍
   - 6.1 初始NPC數量（建議：1個新手鎮，約10-15個NPC，含不同職業和個性）
   - 6.2 初始地點數量（建議：1個新手鎮 + 1個野外區域）
   - 6.3 初始事件類型（建議：3-5種可觸發事件，如戰鬥、偷竊、送禮、對話選擇）
   - 6.4 「活」的驗證標準：玩家做一件事後，能在合理時間內看到世界有反應
```
