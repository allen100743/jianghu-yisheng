## 一、事件系統（Event System）

### 核心結構
```
事件 = {
  觸發條件 (trigger / is_triggered_only)
  多種選項 (option)
  每個選項有：AI 決策權重 + 效果 + 可觸發下一事件
}
```

### 兩種觸發模式
- **自動觸發**：條件滿足時自動出現（如名聲到達閾值）
- **手動觸發**（is_triggered_only）：只能由其他事件/決策調用

### 條件化敘述（同一事件多種文本）
根據角色狀態顯示不同描述：
- 武力 > 150：「英名遠播，義軍願聞其詳」
- 名聲 < 50：「名不見經傳的異人找上門來」

### 事件鏈設計
選項的效果可以觸發另一個事件，形成雙向互動：
```
玩家選擇→向NPC發送反應事件→NPC根據狀態決定回應→回饋事件給玩家
```

**《江湖一生》應用：**
- 結義請求：玩家發出 → NPC根據好感/武力決定接受/拒絕 → 回饋事件
- 仇人追殺：玩家名聲超過閾值 → 自動觸發 → 仇人出現事件

## 二、決策系統（Decision System）

### 核心結構
```
決策 = {
  allowed:    誰可以執行
  visible:    何時在UI顯示
  available:  何時可以執行（成本檢查）
  cost:       資源成本
  days_remove: 多少天後自動過期
  complete_effect: 完成效果
}
```

### 時限性決策
`days_remove = 30` — 30天內不行動，機會消失。
製造緊迫感，逼玩家做選擇。

### 組合成本
```
custom_cost_trigger = {
    has_gold > 500
    has_influence > 100
}
```
不只用一種資源，組合多種成本更真實。

**《江湖一生》應用：**
```
決策：招兵買馬
- available: 名聲 >= 150
- days_remove: 30  # 機不可失，30天後機會消失
- cost: 500銀兩 + 100人脈值
- complete_effect: 增加20名親信
```

## 三、修飾詞系統（Modifier System）——最重要的架構啟示

### 核心哲學：疊加取代分支

**錯誤做法（if-else 分支）：**
```gdscript
if has_faction_member:
    attack += 10
elif is_wounded:
    attack -= 20
elif has_bless:
    attack *= 1.15
```

**正確做法（修飾詞疊加）：**
```
角色基礎武力：70
→ 加上「門派成員」modifier：+10 = 80
→ 加上「受傷」modifier：-20 = 60
→ 加上「受祝福」modifier：×1.15 = 69
最終武力：69（自動計算，無需條件判斷）
```

### 動態修飾詞（帶條件的自動啟停）
```
modifier「狂怒」= {
  enable: 紅怒值 > 80
  remove_trigger: 紅怒值 < 20
  attack_power: +30%
  defense_power: -30%
}
```
每幀檢測條件，自動啟用/移除，不需要手動管理。

### 累積修飾詞（類似傷勢惡化）
```
輕傷：max_hp -10%，恢復速度 -50%
重傷：max_hp -30%，移動 -30%，恢復速度 -80%
瀕死：max_hp -60%，戰鬥力 -70%，自動觸發逃跑AI
```

**《江湖一生》全面應用：**
```
玩家最終武力計算 =
  基礎武力(70)
  + 功法修飾(洗髓經 +20)
  + 裝備修飾(寶刀 +10)
  + 狀態修飾(中毒 -15)
  + 動態修飾(憤怒 ×1.2)
  = 最終：102
```

## 四、資料驅動哲學（最重要的工程啟示）

### HOI4 的鐵律
**所有常數必須在配置檔中定義，禁止硬編碼：**

```lua
-- defines/武功.lua
NMartialArt = {
    BASE_ATTACK_POWER = 1.0,
    ATTACK_POWER_PER_LEVEL = 0.1,
    MAX_MARTIAL_ART_LEVEL = 100,
    SKILL_LEARNING_SPEED_FACTOR = 0.05,
}
```

### 為什麼這樣設計？
- 平衡設計師修改數值不需要程序員
- A/B 測試：改配置檔，不改代碼
- 版本更新：修 Lua/JSON，不重新編譯
- 玩家可以 mod：不懂編程也能改數值

**《江湖一生》應用：**
所有武學威力、NPC觸發條件、事件機率、狀態效果數值
→ 全部放在 `assets/data/` 的 JSON/資源檔
→ GDScript 只讀取，不硬編碼任何遊戲數值

## 五、設計哲學總結

| HOI4 模式 | 《江湖一生》對應 |
|---------|---------------|
| 事件觸發系統 | 江湖奇遇/NPC互動事件 |
| 決策時限機制 | 人生抉擇/時機窗口 |
| 修飾詞疊加 | 角色屬性計算架構 |
| Defines 配置表 | assets/data/ 全部外部化 |
| AI 權重系統 | NPC 行為決策 |

**核心啟示**：
1. **聲明式**優於**命令式**——描述「是什麼」，讓引擎算「怎麼做」
2. **修飾詞疊加**優於**if-else 分支**——數值層疊，邏輯清晰
3. **資料驅動**優於**硬編碼**——策劃改數據，不找程序員
4. **事件鏈**優於**單一事件**——複雜互動由多個小事件構成
