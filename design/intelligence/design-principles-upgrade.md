## 強制應用的設計原則（所有新草稿和修訂版必須遵守）

### 1. Severity 連續值模型（RimWorld）
- **禁止**使用輕/中/重三段離散枚舉
- 所有狀態、成長、關係值都使用 0.0→1.0 連續 severity
- 每個關鍵閾值（0.3 / 0.6 / 0.9）觸發新的 stage 效果
- stage 效果可以是：屬性修飾詞、行為限制、事件觸發、UI 變化

### 2. 修飾詞疊加架構（HOI4）
- **禁止** if-else 分支計算最終屬性
- 所有 buff/debuff 作為修飾詞疊加：`最終值 = (基礎 + Σ加法) × Π(1 + 乘法)`
- 修飾詞可以是：臨時的（有 duration）、條件觸發的（enable/remove_trigger）、永久的
- 設計文件中要明確說明每個修飾詞的類型和疊加方式

### 3. 資料驅動（HOI4）
- 所有數值外部化到配置檔
- 設計文件要說明「可調參數」和「安全範圍」
- 策劃改數值不需要程序員

### 4. 對稱 Trade-off 設計（RimWorld Traits）
- 每個特質/技能/選擇必須有明確的正面和負面
- 不允許「純優點」設計
- 好的 trade-off 格式：「攻擊+8，魅力-300（天煞孤星）」

### 5. 事件鏈而非單一事件（HOI4）
- 重要事件要設計成「觸發 → 選項 → 後果 → 後續事件」的鏈條
- NPC 反應要作為獨立事件設計，不要硬編碼進主事件

## 武俠語言對照（所有草稿必須遵守）

| 禁用（修仙）| 改用（武俠）|
|-----------|-----------|
| 靈力、法力 | 內力 |
| 靈根、資質 | 武學資質、天賦 |
| 修煉（境界）| 練武、武功精進 |
| 丹藥（修仙）| 藥材、金瘡藥、補血藥 |
| 法寶 | 兵器、暗器、神兵 |
| 宗門（修仙）| 門派、幫會 |
