2026-05-12 完成業界研究，結論如下。

**推薦設計方向：嚴重度優先排序型 + 三層視覺語言 + 武俠語境文案**

**Why:** 製作人要求研究多狀態疊加UI，供傷勢與狀態效果系統（6種狀態，severity 0.0-1.0 連續值）的 UX spec 設計參考。

**How to apply:** 起草 design/ux/hud-status-effects.md 時，直接引用此方向。設計決策需報告製作人確認後才能寫入 spec。

## 核心結論

- **三層視覺語言**：圖示填充度（0-100% 反映 severity）+ 3px micro-bar（顏色隨段位）+ 脈衝動畫（≥0.9 時）
- **自動排序**：按緊急度評分（severity × 惡化速率係數 × 致死風險係數），≥0.9 強制置頂
- **危急觸發**：首次進入閾值時一次性動畫，之後靜態光暈（避免持續閃爍讓玩家脫敏）
- **漸進揭露**：HUD 只顯示圖示，懸停展開武俠語境浮框，主動開啟面板顯示疊加後最終屬性

## 競品關鍵發現

- 鬼谷八荒：圖示排列型但無 severity 視覺化，「有/無」標籤設計與我們需求不符
- 龍胤立志傳：狀態資訊埋藏太深，玩家找不到，被評為「2000年代UI」—— 反向標竿
- RimWorld：文字優先型 + 顏色=嚴重度，適合作為詳細面板參考；社群 mod「Nice Health Tab」人體剪影廣受好評
- SCUM：身體映射型但資訊過量，Metabolism 系統被玩家評為「嚇跑人」—— 資訊負擔反教材

## 武俠本地化要點

- 6種狀態各有武俠命名分層（見GDD status-effects-system.md）
- 浮框文案加入一句情境描述（「唐門的蠱毒已侵入臟腑...」）
- 顏色語義：外傷暖紅、內傷深紫、中毒毒綠、疲勞冷灰、飢餓土黃、疾病病黃藍
